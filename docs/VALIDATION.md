## 验证中发现并修复的真问题

这些问题**只有真跑起来才会暴露**，单元测试全部通过时它们依然存在：

1. **sidecar 插件 ID 大小写与 manifest 不一致** → DBX 拒绝启动后端，报 identity mismatch。改动 Go module 路径时漏改了硬编码 ID。已加测试比对入口与 manifest。
2. **快照从不携带 selfId** → 房主认不出自己的座位，每一步都被当观战拒绝。
3. **快照没有 lastMove / inCheck / winLine** → 六类特效全部没有触发条件。
4. **lobby 快照没有棋盘** → 开桌后盘面空白。
5. **Clock 在练习盘上 panic** → `switchTurn` 从 `running = -1` 计算 `1 - running = 2`，索引越界。
6. **白子几乎不可见** → 浅色棋子放在浅色纸面上，需要明确描边。
7. **连五连线画在棋子之上** → 遮挡棋子，改为在棋子层下方。
8. **将军红框从 stage 原点绘制** → 跑到棋盘外，改为使用棋盘原点。
9. **印章是空心方框且落在连线中点** → 改为实心朱章，落在决胜那一手。
10. **场景在已有棋局上重放** → 第二手非法，改为每次从开局重启。
11. **将军大字越出棋盘** → 威胁方常在后排，「将」字以威胁点为中心时有一半掉到纸外。改为按棋盘边界夹取并缩到一格半。
12. **印章盖在棋子下面** → 整个连五特效被放进 `underLayer`（因为连线要在棋子下）。改为拆两层：连线在下、印章在 `overlayLayer` 上。
13. **印章是个红圆点** → 绘制用的是圆形轮廓且没有刻字。改为圆角方形墨块 + 纸色刻框 + 纸色刻字 + 缺墨斑点。
14. **五子棋盘上冒出「将」字** → 切棋种后快照仍带上一局的 `inCheck`。`CheckEffect` 现在只对象棋生效，`setGame` 也会清掉旧特效。
15. **本地预览的四个场景跑同一条棋谱** → `bridge.js` 的 `dev.scenario` 忽略了 `name`。已按 `scenarios.go` 复制四组夹具，预览才能用来验特效。

## 第二轮改版（动效 + UI 重做）

这一轮解决的是**观感**，不是特效数量。核心发现：真实宿主里走子后连拍 5 帧像素完全相同——
`scene.js` 的 `drawPieces()` 每次 `clearPieces()` 把 32 枚棋子全部销毁重建，全项目零补间。
**棋子是瞬移的**，任何落点装饰都救不回来。

### 做了什么

| 项 | 改动 | 证据 |
| --- | --- | --- |
| 棋子移动补间 | 新增 `src/board/pieces.js`：持久化 `PieceNode` 视图 + 快照 diff 识别 move/place/capture，easeOutQuint + 正弦弧抬升 | iframe 内采样 tween 节点：y 从 568 → 504.8 → 490.7 → 489.3，3 个中间帧位置 |
| 特效锚定 | 新增 `scene.schedule()` 队列；落子墨涟漪等棋子真正落地才触发，吃子提前 60ms 与击飞重叠 | 队列在 undo/复盘跳转时清空 |
| 墨晕 | `GlowFilter`（pixi-filters）替掉假加粗描边，字缘有真实湿边扩散 | 将军抓帧：字外沿晕开 |
| 印章压痕 | `DropShadowFilter` 给 `sealGroup` 一点右下偏移投影 | 印章从「贴纸」变成「压进纸里」 |
| 印章位置 | 从「正中盖在决胜子上」改为沿连线方向推开 0.78 格并夹取边界 | 不再压住它要庆祝的那颗子 |
| 粒子 | 缓存单位多边形 + `scratch` 复用数组，粒子 34 → 52 | bundle 只涨 0.14 kB |
| UI 设计系统 | 按 premium-ui skill 重做：完整 token、双色板校验、44px 触控、`focus-visible` 焦点环、`reveal` 交错入场 | `check_ui.py audit` 0 违规 |

### 验证脚本

`scripts/verify-round.mjs` 自带 `dbx-plugin dev` 生命周期 + 随机端口 + 全新 data-dir，
一轮跑完并写 `scripts/out/<tag>/report.json`。**必须每次全新 data-dir**，否则上一次的房间会让
「开桌」按钮消失、`lowMotion` 也会被记住。

## 特效改版后的验证方式

`scripts/capture-effects.mjs`（本地预览）与 `scripts/verify-host.mjs`（真实
`dbx-plugin dev`）会把每个场景按固定毫秒抓帧到 `scripts/out/<tag>/`。后者走
sidecar 真实夹具，是判断特效在真实局面下是否成立的依据；前者只能看形状。

```bash
npm run build
node scripts/capture-effects.mjs baseline        # 只走本地预览
dbx-plugin dev --path . --port 5401 --data-dir /tmp/fx
node scripts/verify-host.mjs 5401 hostfx          # 走真实宿主
```

注意 `--data-dir` 会记住上次的「低动效模式」，复测前用全新目录，否则抓到的全是降级形态。
